# 장애 조사 데스크 평가

두 보고서 비교의 후속 구현과 평가 원본은 [비교 실험](comparison/)에 있다. 아래 표는 해당 변경 이전에 실행한 결과다.

현재 주문 장애의 배포 버전은 **v2.4.0**이다. 과거 보고서에는 **v1.8.0**이 나온다. 이 평가에서는 현재 로그·변경 기록과 과거 문서를 각각 가져와서 두 사건을 구별하고, 필요한 근거가 비면 판단을 보류할 수 있는지 확인했다.

## 최종 버전과 새 질문 7개

**새 질문에서 Qwen은 답변 가능 5개 중 2개, 보류가 필요한 2개 중 2개를 정확히 처리했다.** 각 질문을 세 번 실행한 결과다. 같은 조건의 규칙 모드는 답변 가능 5개 중 4개, 보류가 필요한 2개 중 2개를 처리했다. 개발 질문에서는 Qwen도 답변과 보류를 모두 통과했다.

최초 평가 후 v2 플래너는 9개 보고서 전체에서 기술 용어 후보를 만들고, 로컬 Qwen이 질문에 따라 로그와 문서의 검색어를 선택하도록 바뀌었다. 검증기는 현재 증상·배포와 문장의 일치 여부를 확인한다. 기존 세트를 다시 측정한 결과는 회귀 검사다. 별도 평가자가 새로운 질문과 정답을 고정하고 구현 담당자에게 공개하지 않은 채 두 모드가 확정된 뒤 실행했다. 새 세트도 최초 평가와 동일한 합성 사건·보고서를 사용한다. Qwen은 02의 게이트웨이 504에 대해 MySQL 로그를 찾았지만 문서 검색어로 `No space left on device`를 골랐다. 04의 영어 간접 표현에서는 `search-service`를 선택해 로그가 비었다. 두 모드 모두 05의 두 보고서 비교를 입구에서 거절했다. 필요한 두 문서가 코퍼스에 있기 때문에 원래 정답은 비교 설명이며, 이 거절은 실패로 셌다. 나머지 두 사례에서는 서로 충돌하는 배포 기록과 확인할 수 없는 영향 고객 수를 올바르게 보류했다.

## 최초 블라인드 평가

개발 질문 6개와 별도 보류 질문 10개를 각 모드에서 3회씩 실행했다. 총 96회, 서로 다른 질문은 16개다. 보류 질문에는 답할 수 있는 질문 3개와 보류해야 하는 질문 7개가 있다. 고정 시드·온도 0에서 반복 결과는 같았다. 비율의 분모에는 반복 실행이 포함된다.

| 모드 · 분할 | 관련 문서 회수 | 도구 선택 | 도구 실행 | 근거 답변 | 올바른 보류 | 전체 | 지연 p50 / p95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 규칙 · 개발 | 6/6 | 15/15 | 30/33 | 6/6 | 12/12 | 18/18 | 0.95 / 2.31초 |
| Qwen · 개발 | 6/6 | 15/15 | 30/33 | 3/6 | 12/12 | 15/18 | 4.81 / 9.75초 |
| 규칙 · 보류 | 12/12 | 24/24 | 51/57 | 6/9 | 21/21 | 27/30 | 1.08 / 1.63초 |
| Qwen · 보류 | 6/12 | 24/24 | 51/57 | **0/9** | **21/21** | 21/30 | 1.98 / 8.71초 |

최초 검증기는 주문 커넥션 풀 보고서의 문서 ID를 코드에 직접 지정했다. 문서 회수 점수는 검색기가 반환한 원자료로 따로 계산했지만, 이 버전의 답변 검증을 새로운 사건·문서에 일반화하기는 어렵다.

Qwen은 보류 질문의 답변 가능 사례 세 가지를 매번 보류했다. 21/30은 7종류의 올바른 보류에서 나왔다. 반면 개발 세트의 영어 질문에서는 현재 배포와 로그, 과거 보고서를 모두 인용했다. 범위 밖 요청과 플래너 대역은 로컬 모델을 호출하지 않는다. 모델 서버가 실제 처리한 33회에서 개발은 입력 3,642 / 출력 473토큰, 보류는 입력 6,453 / 출력 840토큰을 사용했다.

## 어떤 단계에서 실패했나

| 사례 | 원자료에서 확인한 현상 |
|---|---|
| 개발 01 · 한국어 원인 질의 | Qwen의 로그 검색어 `order failure`가 정상 주문 조회 로그를 가져왔다. 관련 과거 보고서는 있었지만 현재 장애 로그를 확보하지 못했다. |
| 보류 01 · 한국어 간접 표현 | Qwen은 `timeout`으로 504 로그를 찾았다. 보고서 검색어에는 “비슷한 과거 보고서와 현재 로그를 같이 확인해 주세요”가 남아 주문 커넥션 풀 문서가 상위 4개 청크에 없었다. |
| 보류 02 · 영어 간접 표현 | Qwen은 올바른 보고서를 찾았다. 로그 검색은 circuit breaker 이벤트를 반환했고 현재 검증기가 요구하는 커넥션·쿼리·504 증상이 부족했다. |
| 보류 03 · 두 보고서 비교 | 규칙 모드는 검색 결과에 두 문서를 모두 포함했지만 커넥션 풀 문서 하나만 인용하고 캐시 장애와의 차이를 답하지 않았다. `verified` 응답도 평가에서는 실패다. Qwen은 보고서 검색어 `past incidents`를 만들고 판단을 보류했다. |
| 보류 05–10 · 고장 주입 | 서로 다른 주문 배포, MCP 오류 응답, HTTP 503 플래너 대역, 빈 보고서, 잘못된 정수 인자, 로그 호출 타임아웃을 독립적으로 주입했다. 각 실행에서 원인별 상태와 빈 인용 목록을 검사했다. |

## 판정과 재현

- **문서 회수**는 답변 가능 질문의 정답 문서가 MCP가 반환한 상위 4개 청크에 있었는지 측정한다. 같은 문서의 여러 청크는 한 번만 센다. 두 문서 비교 질문의 분모는 2다.
- **도구 선택**은 실행 전 검증을 통과한 도구 이름 집합을 정답과 대조한다. 조사에는 세 도구가 필수이고 범위 밖 요청은 빈 집합이 정답이다. 플래너 오류·잘못된 인자 사례는 이 분모에서 뺐다. 이 지표는 계획의 순서나 검색어 품질을 채점하지 않는다.
- **도구 실행**은 실제 시도한 MCP 호출 중 스키마 검사를 통과한 횟수다. 빈 검색 결과도 프로토콜상 성공이다. 분모에는 주입한 오류가 포함된다. 외부 서비스의 가동률을 측정한 값으로 해석할 수 없다.
- **근거 답변**은 정답 상태, 배포 버전과 증상 표현, 요구된 세 종류의 출처 및 모든 정답 문서 인용을 검사한다. 로그/변경 ID와 실제 문장을 비교하며, 보고서는 문서명과 본문 해시 및 원문을 대조한다. 이 자동 규칙만으로 자유 서술의 모든 문장을 검증할 수는 없다.
- **올바른 보류**는 `withheld`, 사전에 정한 원인 코드, 빈 인용을 모두 요구한다. 빈 로그/문서는 실제 도구 결과를 비우고, 타임아웃은 호출 경계에서 예외를 주입한다. HTTP 503은 플래너 대역에서 발생시킨다. 모델 서버 장애를 직접 확인한 별도 기록도 있다. [플래너 연결 점검](local-planner-probe.json)
- 각 질문은 새로운 MCP stdio 프로세스를 열고 캐시 없이 실행한다. 시간에는 시작·탐색·모델·도구·그래프 종료가 포함된다. Linux x86-64 CPU에서 여러 평가 프로세스가 겹쳐 실행됐다. 지연은 이 호스트의 관측값이다. 모델·의존성·구현 지문과 요청 ID는 원자료 및 요약 JSON에 기록했다.
- 자료는 한국어 예시 보고서 9개와 `db_pool_exhaustion` 시드 42의 단일 합성 장애다. Qwen과 규칙 모두 기본 해시 임베딩 + BM25/RRF를 사용했다. 보고서 9개에 대한 별도 ONNX 측정은 [임베딩 실험 원자료](served-embeddings.json)에 있다.

저장소 루트에서 데스크의 Python 의존성을 설치한 뒤 실행한다. 로컬 모드는 먼저 [Qwen 서버 실행 문서](../local-model.md)에 따라 서버를 띄운다. `--results-dir`로 새 디렉터리를 지정하면 기존 원자료를 보존할 수 있다.

```sh
python scripts/desk_eval.py --mode offline --split development --repeats 3 --results-dir /tmp/desk-eval
python scripts/desk_eval.py --mode local --split heldout --repeats 3 --results-dir /tmp/desk-eval
python scripts/desk_eval.py --mode local --split challenge --repeats 3 --results-dir /tmp/desk-eval
```

평가 환경은 저장소 루트에서 `python -m pip install -e .`로 설치할 수 있다.

평가 중 코퍼스나 라벨의 SHA-256이 달라지면 CLI가 실행을 중단한다. 평가 코드는 LLM 판정기를 사용하지 않는다. 실패한 실행도 원자료에 보존한다. [채점 코드](../../../scripts/desk_eval.py)

## 질문 범위 검사 회귀

최초 평가 뒤 도메인 단어 사전을 적용한 중간 버전은 규칙 모드 개발에서 18/18을 유지했지만 같은 보류 질문에서는 **27/30 → 9/30**으로 떨어졌다. 보류해야 할지 올바르게 구분했는지도 원인 코드까지 검사하기 때문에, 실제 도구 장애가 일어나기 전에 범위 밖으로 거절한 경우는 실패로 남는다. 최초 결과와 이 회귀를 구분해 보존했다. [중간 버전의 실행과 구현 지문](scope-regression/)
