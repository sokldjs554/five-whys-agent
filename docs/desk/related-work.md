# 장애 조사 도구와 한국어 검색 프로젝트 비교

**HolmesGPT가 공개한 ‘주문 서비스 지연’은 이 데스크와 가장 가까운 비교 사례다.** 둘 다 배포 이후 느려진 주문 요청을 조사하지만, 답을 검증하는 방법이 다르다. HolmesGPT의 해당 문항은 Kubernetes 환경에서 찾아야 할 설명을 지정한다. 이 데스크에서는 답에 붙인 배포·로그·문서가 실제로 같은 실행에서 반환됐는지, 증거가 빠지면 보류하는지까지 고정 사건에서 반복 검사한다. 두 도구의 정확도를 같은 데이터에서 비교한 실험은 수행하지 않았다. [비교 문항](https://github.com/HolmesGPT/holmesgpt/blob/0e55d511caaa71e2a9096b6c4d309c7b22a0f348/tests/llm/fixtures/test_ask_holmes/07_high_latency/test_case.yaml) · [데스크의 사례·판정 기준](evaluation/README.md)

## 공개 소프트웨어에서 확인한 구현

|---|---|---|
| **HolmesGPT** · 해외 SRE 조사 에이전트 | 모델의 도구 호출을 실행하는 루프에 중복 호출 방지와 컨텍스트 길이 제어가 있다. 지연 문항은 매니페스트로 환경을 만들고 예상 설명에 DB 호출 5~10초를 명시한다. 공개 고속 벤치마크에는 판정 모델·반복 횟수가 있으며 Argo CD 조사 화면도 공개돼 있다. [도구 루프](https://github.com/HolmesGPT/holmesgpt/blob/0e55d511caaa71e2a9096b6c4d309c7b22a0f348/holmes/core/tool_calling_llm.py) · [고정 문항](https://github.com/HolmesGPT/holmesgpt/blob/0e55d511caaa71e2a9096b6c4d309c7b22a0f348/tests/llm/fixtures/test_ask_holmes/07_high_latency/test_case.yaml) · [평가 결과](https://github.com/HolmesGPT/holmesgpt/blob/0e55d511caaa71e2a9096b6c4d309c7b22a0f348/docs/development/evaluations/fast-benchmark-results.md) · [조사 데모](https://github.com/HolmesGPT/holmesgpt/blob/0e55d511caaa71e2a9096b6c4d309c7b22a0f348/docs/assets/Holmes_ArgoCD_demo.gif) | 사용자는 장애 원인을 확인하고 싶지만 모델이 같은 검색을 반복하면 대기 시간만 늘어난다. 이 데스크의 기본 조사는 세 종류의 읽기 도구로 제한하고 첫 도구·검색어 선택을 모델에 맡긴다. 이에 따라 한 번의 실패를 원문까지 재현하기 쉬워졌고, 등록되지 않은 시스템을 추가 탐색하는 범위는 줄었다. | **AutoRAG / Marker-Inc-Korea** · 국내 공개 프로젝트 | 현재 TypeScript 에이전트는 출처·구절을 구별하는 근거 키를 만든다. 같은 리비전의 `legacy/`는 별도 Python 평가 도구다. 한국어 예제는 top-3 검색의 precision/recall/F1과 생성 지표를 각각 설정하고, 테스트는 MRR·nDCG도 개별 검사한다. [근거 식별 코드](https://github.com/Marker-Inc-Korea/AutoRAG/blob/4579957698d51b75651b9eaa02db4022f3424187/src/retrieval/evidence-id.ts) · [한국어 설정](https://github.com/Marker-Inc-Korea/AutoRAG/blob/4579957698d51b75651b9eaa02db4022f3424187/legacy/sample_config/rag/korean/non_gpu/simple_korean.yaml) · [측정식 테스트](https://github.com/Marker-Inc-Korea/AutoRAG/blob/4579957698d51b75651b9eaa02db4022f3424187/legacy/tests/autorag/evaluate/metric/test_retrieval_metric.py) | 장애 보고서 하나가 검색돼도 현재 배포를 입증할 수는 없다. 데스크는 과거 보고서 회수와 현재 로그·변경 근거를 갖춘 답변을 별도로 채점한다. 실제로 최초 평가에서 Qwen은 반복을 포함해 기대한 정답 문서 회수 12건 중 6건에 성공했지만 답변 가능 실행 9회에서 근거를 모두 갖춘 답은 0회였다. [최초 실행·분모](evaluation/initial/local-heldout-summary.json) · [근거 확인 코드](../../src/fivewhys/desk/evidence.py) |
| **KURE / 고려대학교 NLP & AI 연구실** · 한국어 검색 임베딩 | late interaction 측정 코드는 질의별 정답 문서와 코퍼스를 정렬해 색인 방식을 비교한다. LawIRKo 공개 기록에는 GPU, 색인 크기, nDCG@10, 질의 인코딩·검색 구간별 지연이 함께 있다. [측정 코드](https://github.com/nlpai-lab/KURE/blob/e394fc16141a0ae40dd2bfda33d1afb943d4db08/deploy/late-interaction/run.py) · [동일 데이터의 색인별 JSONL](https://github.com/nlpai-lab/KURE/blob/e394fc16141a0ae40dd2bfda33d1afb943d4db08/deploy/late-interaction/results/LawIRKo.jsonl) | 로컬 면접 데모에서는 CPU로 9개 보고서의 54개 구절을 처리하므로 작은 다국어 MiniLM을 선택했다. 실제 인코더 요청과 합성 벡터 4,096행의 삽입 비용은 서로 다른 측정이다. KURE의 법률 문서·GPU 수치를 장애 검색의 품질 또는 처리량에 전용하지 않았다. [인코더와 측정 조건](embeddings.md) |
| **Scouter** · 오픈소스 APM | XLog 클라이언트는 선택한 트랜잭션 ID로 프로파일 데이터를 조회한다. 공식 화면에는 한 트랜잭션의 프로파일이, 문서에는 SQL 분석 및 전체 프로파일 저장 기능이 보인다. ## 상용 제품에서 확인할 수 있는 범위

- **Datadog Bits Investigation.** 공개 안내서는 운영 알림에서 가설을 세우고 관련 텔레메트리를 반복 수집하는 조사를 설명한다. 이 데스크의 출발점은 사용자가 고른 합성 사건이며 원본 데이터가 고정돼 있다. 이 방식으로 같은 입력의 실패·수정 결과를 공개할 수 있다. 운영 알림 탐지부터 여러 계정의 실시간 텔레메트리를 뒤지는 기능은 검증 범위 밖이다. [Datadog 제품 설명](https://docs.datadoghq.com/bits_ai/bits_ai_sre/) · [데스크 실행 환경과 재현](README.md)
- **와탭 Java APM.** 공식 안내서의 히트맵에서 구간을 지정하면 해당 트랜잭션 목록과 하위 스텝을 함께 열 수 있다. 사건의 핵심 문장을 먼저 읽고 필요할 때 근거로 내려가는 데스크의 흐름과 비교했다. 사용자 트래픽을 계측하는 와탭과 달리 데스크의 공개 화면은 저장된 조사 기록을 재생한다. 이 차이를 화면에 표시하고 로컬 API의 신규 조사 경로를 별도로 제공한다. [와탭 공식 트레이스 분석 화면·조작](https://docs.whatap.io/java/dashboard-hitmap-trace) · [데스크 화면과 데이터 출처](design.md)

2026-11-27 공개된 소스·테스트 정의·저장된 측정 결과와 공식 제품 자료를 확인했다. 외부 오픈소스의 실행 결과는 각 프로젝트가 공개한 값이며, 상용 서비스는 로그인한 고객 환경에서 시험하지 않았다. 이 비교에서 외부 프로젝트의 코드·이미지는 가져오지 않았다. HolmesGPT·AutoRAG의 코드는 Apache-2.0, KURE 저장소의 코드는 MIT이며 모델별 사용 조건은 모델 카드에 있다. Scouter의 라이선스 파일에는 Apache-2.0 전문이 수록돼 있다.
