# 장애 조사 데스크 화면 설계와 검증

서비스 운영자와 구현을 검토하는 엔지니어가 주문 서비스 모의 장애의 질문 하나를 고르고, 결론의 특정 문장에서 로그·변경 기록·과거 보고서로 이동해 판단을 확인하는 화면이다. 첫 화면에는 저장된 실행 하나를 열어 둔다. 카드의 답변과 인용, 도구 호출 횟수는 같은 실행의 원자료에서 가져온다. [공개용 실행 원자료](../../desk-demo/runs.json)

자료는 제조사가 공개한 제품 화면과 문서에 한정했다. 업체 콘솔 계정으로 현재 버전을 측정하거나 공통 사용성 개선 효과를 평가한 자료는 없다. 와탭과 Sentry의 화면을 먼저 확인해 구조를 정했고, NHN Cloud와 Grafana 사례는 첫 구현 후 검색·상세 열기의 동작을 대조하는 데 사용했다. CLOVA Studio, Dify, n8n의 공식 화면을 추가로 확인한 뒤 검색어 미리보기, 반환 건수, 모델 사용량 표시를 보강했다.

## 사용 흐름

1. 첫 화면의 질문 원문, 엔진과 실제 호출 수를 확인한다. 모의 장애용 데이터이며 공개 페이지의 기록 선택에는 계정과 API 키가 필요하지 않다.
2. **조사 기록 선택**에서 제목·질문·도구명·기록 ID를 검색한다. **판단 보류**를 선택하면 보류한 사례만 남는다. 결과가 한 건도 없으면 조건을 바꿀 수 있다.
3. **조사 결과**에서 근거 번호를 누르면 대응하는 원문이 열린다. 오류 주입이나 평가 미통과가 기록된 사례는 결과 옆에 그 조건을 표기한다.
4. **도구 호출 기록**에서 원하는 단계의 요청과 반환 JSON을 연다. 공개 화면은 저장된 자료를 다시 읽는다. 같은 화면을 로컬 API의 `/desk/`에서 열면 엔진을 선택하고 새 질문을 접수할 수 있다.

## 화면과 접근성

넓은 화면에는 결론과 근거 원문을 나란히 두고 작은 화면에서는 결론 다음에 근거를 놓았다. 짙은 보라색 표지, 밝은 종이색 본문, 인용 번호의 보라색, 판단 보류의 황갈색을 사용했다. 상태에는 항상 문구가 함께 표시된다. 파일 일러스트의 수는 현재 로드한 기록 건수다.

검색은 키보드로 조작할 수 있는 대화상자이며 Esc로 닫는다. 원문은 의미를 보존하도록 줄바꿈하고, 긴 도구 출력은 포커스 가능한 영역에서 열람한다. 로딩, 빈 아카이브, 검색 결과 없음, 불러오기 실패와 재시도, 실행 중단을 별도로 처리한다. 화면 검증은 Chromium을 사용했다. Safari·Firefox·모바일 실기기 및 화면 낭독기의 발음·탐색은 검증 범위 밖이다.

### 검증 다시 실행하기

로컬 데스크 API를 실행한 상태에서 Playwright Python과 Chromium이 있는 환경으로 다음 명령을 실행한다. 검증 과정에서 로컬 작업 대기열에 규칙 기반 질문 한 건이 추가된다. llama.cpp 서버를 실행한 경우 `--live-model`을 더하면 기본 기록의 질문으로 모델 조사도 한 건 실행한다. `--captures`를 생략하면 스크린샷을 저장하지 않는다.

```bash
python docs/desk/check_ui.py --base-url http://127.0.0.1:8750 --captures docs/desk/captures
```
